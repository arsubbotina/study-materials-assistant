# Study Materials Assistant

Учебный помощник для сбора ссылок, классификации материалов по предметам
и поиска по текстам с TF-IDF. Автор — Анастасия Субботина.

## Задача

Собрать учебные материалы в локальный каталог и находить фрагменты для подготовки
к экзаменам. Проект объединяет три учебных задания:

- `collect_cli.py` — получает текст страницы, определяет предмет через GigaChat,
  сохраняет ссылку в JSON и строит отчёт за период.
- `telegram_bot.py` — предоставляет сбор ссылок и отчёты через Telegram.
- `search.py` — разбивает материалы на фрагменты, строит TF-IDF-индекс,
  ранжирует фрагменты по косинусному сходству и передаёт их GigaChat для ответа.

Предметы: численные методы, компьютерные сети, программирование на Python, физика.

## Как работает поиск

`requests.json → загрузка HTML → очистка текста → фрагменты → TF-IDF → cosine similarity → GigaChat`

Размер фрагмента — 900 символов, перекрытие — 180. Используются униграммы и
биграммы, максимум 60 000 признаков. Предмет запроса выбирается по сумме
релевантности 12 найденных фрагментов; в ответ передаются до 8 фрагментов
выбранного предмета. В консоли выводятся ответ и ссылки на источники.
Это лексический поиск с генерацией ответа по контексту; качество поиска и
точность ответов на отдельной размеченной выборке пока не измерялись.

## Запуск

Нужны Python 3.10+, ключ GigaChat и токен Telegram только для режима бота.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env` своими ключами и экспортируйте их в macOS/Linux:

```bash
set -a
source .env
set +a
python collect_cli.py
```

Введите URL. Для отчёта по всем предметам:

```text
ОТЧЕТ все 2026-01-01 2026-12-31
```

`q` завершает CLI. Telegram-режим запускается отдельно:

```bash
python telegram_bot.py
```

Для поиска сначала соберите каталог через CLI или используйте демонстрационные
ссылки. Пример содержит публичные страницы Python и не является результатом
пользовательского исследования:

```bash
cp examples/requests.example.json requests.json
python search.py
```

Введите тему, например `списки Python`. При первом запуске создаётся
`tfidf_index.pkl`. После изменения каталога удалите только свой локальный индекс,
чтобы он перестроился. Запускайте программы из корня репозитория. Не запускайте
CLI и Telegram-сборщик одновременно: они записывают один JSON-файл.

## Ограничения

- Telegram-версия использует общий каталог без разделения по пользователям.
  Это личный прототип: не размещайте его как открытый многопользовательский сервис.
- Команда отчёта разбирается через `split`; названия предметов с пробелами
  пока не поддерживаются корректно. Для демонстрации используйте `все`.
- Сборщик работает со статическим HTML; PDF и динамические страницы не поддержаны.
- Нет полноценной обработки недоступных URL, ошибочного JSON от LLM и пустого индекса.
- Даже при нулевом сходстве поиск может вернуть фрагменты: нужен порог релевантности.
- Индекс не обновляется автоматически; pickle-файлы можно загружать только
  созданные самостоятельно, поскольку чужой pickle может выполнять код.
- Тексты страниц и запросы отправляются в GigaChat. Не используйте личные данные.
- Проверка TLS включена; для окружения GigaChat может понадобиться доверенный CA.

## Проверка и дальнейшая работа

```bash
python -m unittest discover -s tests -v
```

Offline-проверки охватывают фильтрацию отчёта по датам и перекрытие фрагментов.
Синтаксис всех модулей проверен. Полный сценарий с внешними API не проверен при
подготовке репозитория; зависимости ещё не зафиксированы в проверенном lock-файле.
Следующие шаги: исправить разбор команд, разделить данные пользователей,
добавить обработку ошибок и оценить поиск на наборе вопросов с известными ответами.

## Подготовка к публикации

Файлы переименованы по назначению, ключи вынесены в переменные окружения,
проверка TLS включена. Пользовательские JSON, индексы и `.env` исключены из Git.
